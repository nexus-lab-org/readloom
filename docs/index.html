About

readloom replaces the reflex of reaching for python -m http.server to browse a directory of notes. It renders markdown properly, turns fenced ```mermaid blocks into pannable, zoomable diagrams, and gives source files an editor-grade syntax-highlighted view — all while keeping raw assets (.js, .css) referenced by your own .html pages working exactly as before.

One server instance can host any number of independent directories, each under its own named root, listed on a landing page.

Features

Markdown + Mermaid

GitHub-flavored markdown, with Mermaid diagrams rendered pannable and zoomable — scroll to zoom, drag to pan, one click to maximize to fullscreen.

Editor-grade highlighting

Shiki-powered code view using real VS Code TextMate grammars, with line numbers, for any language it bundles.

Multi-root

Host several directories from one server via roots.yml, each under its own URL prefix, listed on the landing page.

Asset-safe

Bare file URLs always serve raw content, so <script src> and <link> references in your own pages never break.

Fail-fast config

A bad root name or a path that doesn't exist stops the server at startup with a clear error, not a silent 404 later.

Docker or npx

Same codebase, two ways to run it: a Docker image for volume-mounted directories, or zero-install npx for local use.

Quick start

Serve a single directory — the root name is derived from its basename:

npx readloom ~/some-directory

Serve more than one at once:

npx readloom ~/teach ~/some-other-project

Or use a config file for named roots:

# roots.yml
teach: /home/you/teach
sentinel-services-design: /home/you/code/sentinel-services/docs/design
npx readloom --config roots.yml

CLI options

FlagEnv varDefaultDescription

—PROMPT_USERasif@readloomThe user@host shown in the breadcrumb prompt

Docker

docker build -t readloom .
docker run -d --name readloom \
  -v ~/teach:/docs/teach:ro \
  -v ./roots.yml:/app/roots.yml:ro \
  -p 8000:8000 --restart unless-stopped readloom

Paths inside roots.yml are interpreted differently depending on how you run readloom: real host paths for npx/node, container-internal paths (with matching -v mounts) for Docker.
